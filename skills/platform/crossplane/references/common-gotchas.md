# Common gotchas

- **Trim-collapse bug** — `{{-` on its own line eats the preceding newline via the left-trim. For YAML keys with list values, the parent key and the first list item collapse onto one line; the k8s.io decoder rejects with `block sequence entries are not allowed in this context` or `mapping values are not allowed in this context`. The error is reported against the *parent* key (`queue: - id: ...`), not the range directive — confusing.
  **Primary fix: drop the left-trim** — use `{{ range }}` / `{{ end }}` (no `-`).
  **Secondary (can fail):** inline (`queue: {{ range $i, $q := $queues }}`) — the Go template parser may reject with `missing value for range`.
  **Filter lines:** drop `{{-` from `{{- if $x }}` before filter/mapping keys.
  **Data-block collapse:** precompute before the block, not between key and value.
  Read SKILL.md §0 for the full detail.
- **XRD is `apiextensions.crossplane.io/v2`** with `scope: Namespaced` (or `Cluster`). If you set `claimNames` or `connectionSecretKeys` outside `LegacyCluster` scope, the v2 XRD rejects the field.
- **Composition is `apiextensions.crossplane.io/v1`** (the only version that exists). Don't try `apiextensions.crossplane.io/v2` for the Composition.
- **Every composed resource needs `setResourceNameAnnotation "key"`.** Without it, the function either rejects the resource (in newer versions) or mis-routes it as a status update on the XR.
- **Missing `kind:` in a composed resource produces `Object 'Kind' is missing`** — every composed resource must have `kind: ResourceKind` between `apiVersion:` and `metadata:`. Omitting it is a common edit overshoot when rewriting a `metadata:` block; `crossplane render` rejects the entire pipeline step with an error that does not name the resource.
- **`.observed.resources` is nil on first reconcile.** Guard the index call. `dig "status" "vpcId" "" .observed.resources.vpc` panics because Go templates can't field-access a nil map; use `(index $.observed.resources "vpc")` instead so the nil-receiver is the index call, not a field access.
- **`function-auto-ready` is the last step.** Putting it before the render step means it sees no composed resources and the XR will never become ready.
- **`crossplane.io/external-name` on resources where the provider derives its own?** Creates a perpetual diff — the provider overwrites it on every reconcile, the composition reverts it on the next render. Examples: SQS Queue (provider uses queue URL), S3 BucketNotification (provider uses bucket name). **Fix:** never set `external-name` in templates — the provider derives it automatically from `metadata.name`.
- **Indentation off by one space inside `template: |`?** YAML will parse but resources will have wrong fields. Render the template to a file and `kubectl apply --dry-run=client -f -` to validate, or use `crossplane render`.
- **You composed a `Secret` for connection details but the data map is empty?** That's the first reconcile — the underlying instance hasn't produced `connectionDetails` yet. The `{{ if eq $.observed.resources nil }}` (or the more specific `{{ if not (index $.observed.resources "pg") }}`) guard will keep the function from panicking; the map fills in on the next reconcile.
- **Provider CRD not present after install?** Some providers ship CRDs as `Inactive` MRDs under safe-start. Patch the MRD to `Active`, or configure a `ManagedResourceActivationPolicy`.
- **`xprin test` (or a standalone `render.sh`) fails with "crossplane: command not found"** — install the `crossplane` CLI 1.15+ and ensure it's on PATH, or set the path in `~/.config/xprin.yaml` under `dependencies.crossplane`. If this repo pins tool versions via `mise`, run `mise use crossplane@2.3.1` (matches `scripts/render.sh`'s pinned version) rather than installing globally.
- **`xprin test` hangs or "cannot connect to Docker daemon"** — xprin shells out to `crossplane render`, which runs Composition Functions in Docker. Start Docker, or pass `--crossplane-binary` to `crossplane render` for Development-mode functions. Podman works as a Docker alternative.
- **`field not declared in schema` doesn't always mean the field doesn't exist** — it can mean the field exists at a different nesting depth than you assumed. Check CRD properties level by level with `kubectl get crd <plural>.<group> -o jsonpath='{.spec.versions[0].schema.openAPIV3Schema.properties.spec.properties}' | python3 -c "import sys,json;d=json.load(sys.stdin);print(list(d.keys()))"`. If the target field lives under a nested object (e.g. `spec.destination.transformation` not `spec.transformation`), extend the path.
- **`no matches for kind "X"` on apply, even though the CRD exists** — the templated `kind` is a guessed PascalCase, not the real one. Acronyms don't PascalCase naively: `bucketacls` → kind `BucketACL`, not `BucketAcl`. Confirm with `kubectl get crd <plural>.<group> -o jsonpath='{.spec.names.kind}'`. `crossplane render` will not catch this — it doesn't validate against real CRDs; only a schema-validating apply (`kubectl apply --dry-run=server`/`--dry-run=client`) does.
- **A schema field that's semantically one config block can still be `type: array`** — upjet mirrors the upstream Terraform schema, and Terraform `TypeList`/`MaxItems(1)` blocks (e.g. `filter`, `expiration` inside a lifecycle rule) surface as `array` even when only one item is meaningful. Check the schema `type` before assuming object shape; wrap a singular value as a one-item list.
- **User-provided strings in `metadata.name` must be RFC 1123 compliant** — when map keys from user input are used as `metadata.name` segments (e.g. `{{- range $k, $v := .spec.policyArns }}`), keys with underscores or uppercase letters produce invalid K8s names. **Fix:** sanitize with `replace "_" "-" | lower`. Example: `{{- $safeName := $k | replace "_" "-" | lower }}`.
- **Crossplane overrides `metadata.namespace` on native resources** — for composed native K8s resources (v1 ServiceAccount, Secret), Crossplane sets `metadata.namespace` to the composite's namespace regardless of what the template emits. You cannot place a native resource in a different namespace than the XR. Managed resources from providers (IAM Role, SQS Queue) respect the template's namespace.
- **XR stuck `Synced: False — Unsynced resources: <key>` and the MR is 404 (never created)** — the composition's SSA apply was rejected before the object landed. First suspect: the CRD carries a CEL rule (`x-kubernetes-validations`) on `spec.forProvider.*` that the template doesn't satisfy. Upjet providers ship these (e.g. `bucketloggings.s3.aws.m.upbound.io` requires `spec.forProvider.targetPrefix` unless `managementPolicies` drops Create/Update). `make test`/xprin stays green — it validates rendered output, not the real CRD. **Diagnose:** `kubectl get crd <plural>.<group> -o jsonpath='{.spec.versions[0].schema.openAPIV3Schema}' | grep -A3 x-kubernetes-validations` — the rule names the required field. **Fix:** always emit the required field; quote empty-string defaults (`targetPrefix: "{{ $loggingTargetPrefix }}"` renders `""`, a present string). Unquoted, an empty default renders `targetPrefix:` (null), which the structural schema prunes and the CEL `has()` fails again. `kubectl apply --dry-run=server` catches this class of error; xprin never does.
- **Label/annotation values have their own charset — repo paths are not values.** `/` is illegal in label values (and in label key name segments); values max 63 chars. A template stamping a path (`modules/workloads/app`) as a label value passes every render test and fails admission at apply time. Sanitize with `replace "/" "-"` or carry the value in an annotation instead (annotations are free-form, bounded only by total object size).
- **After structural edits to a multi-doc manifest (RBAC consolidation, moving objects between files), assert the document set mechanically before committing**: `[d for d in yaml.safe_load_all(open(f)) if d]` — check the object count, exactly-one per `metadata.name`, and for ClusterRoles the rule-block count. A misplaced insertion can produce a stray rules-less `ClusterRole` (duplicate keys, no `---` separator) that strips a service account's grants cluster-wide the moment it syncs.
